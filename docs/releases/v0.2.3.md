# Codex Squire v0.2.3

发布日期：2026-10-10

本次更新为 Tauri 桌面本地模式加入自动认证，同时保持浏览器访问的管理令牌要求，并改善桌面端口配置的可靠性。

## 新增与改进

### 桌面本地模式自动认证

- 在 Tauri 启动器选择本地模式并成功启动后，直接进入管理界面，无需手动输入管理令牌。
- 刷新页面时自动恢复当前运行实例的认证，不重复启动后端。关闭桌面应用时回收后端子进程。
- 自动认证仅授权给本应用的本地窗口及其托管的后端实例。后端管理 API 仍要求有效的 Bearer Token。
- 自动取得的令牌只保留在前端会话内存中，不写入浏览器存储、URL 或公开运行时信息。

### 浏览器与服务模式登录

| 使用方式 | 登录要求 |
| --- | --- |
| Tauri 本地模式内置窗口 | 自动认证，无需输入管理令牌 |
| Tauri 服务模式内置窗口 | 手动输入管理令牌 |
| 普通浏览器，包括 `127.0.0.1`、`localhost` 与局域网地址 | 手动输入管理令牌 |

- 手动登录会话按后端地址隔离，刷新时校验当前标签页会话；退出管理后清理会话。
- 本地认证失败时提供重试；管理会话失效后取消旧请求，本地自动恢复最多尝试一次，修改操作不会自动重放。
- 管理接口与网关测试的认证失败分别处理，临时网络故障不会直接删除有效的手动登录会话。
- 原生窗口限制外部导航，管理请求及网关测试拒绝 HTTP 重定向，降低凭据被带到其他地址的风险。

### 桌面端口配置可靠性

- 端口配置未变化时不重复写入文件，减少无必要的文件操作及启动失败。
- Windows 下使用原子替换更新已有配置文件，支持后续修改已保存的端口。
- 配置读取失败时仍可编辑端口，提供恢复默认和重新读取入口。
- 端口保存失败时停止本次启动并回收已启动的后端及静态服务，避免界面显示失败而服务仍在后台运行。
- 端口被占用时明确报错，不自动改用其他端口。

## 发行包与使用

- 发行文件：`Codex-Squire-0.2.3-windows-x64.zip`，适用于 Windows x64。
- 解压后运行 `codex-squire-desktop.exe`。包内包含 Java 17 runtime、后端 JAR 和前端资源，无需单独安装 Java 或配置资源路径。
- 系统仍需具备 Microsoft Edge WebView2 Runtime；此便携包不会自动安装 WebView2。
- 默认后端端口为 `18787`，服务模式前端端口为 `18788`，可在启动器修改。
- 本地模式使用 Tauri 内置页面，没有可供普通浏览器打开的独立前端 HTTP 端口。需要浏览器访问时使用服务模式；局域网访问须明确启用对应选项并设置公布地址。
- 发行包不包含用户数据或令牌。升级前关闭旧版本；备份时应保存整个数据目录，包括数据库和密钥文件。

## 升级提示与限制

- 旧版 `squire.adminToken` 存储不会迁移。升级后，浏览器和服务模式需要重新输入一次管理令牌；Tauri 本地模式自动认证。
- 一键修改 Codex 配置文件尚未实现，本版本不会自动改写 Codex 配置。
- 服务模式适用于受信任局域网，当前未提供 TLS、多用户权限隔离或登录失败限流，请勿直接暴露到公网。
- 本次发行面向 Windows x64；跨平台、干净机器安装和异常退出下的完整进程治理仍需后续验收。
